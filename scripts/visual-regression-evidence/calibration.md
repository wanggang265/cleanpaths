## 1. 阈值定义（scripts/visual-regression.cjs 写死）

| 参数 | 值 | 含义 |
|---|---|---|
| `CH_TOL` | 24 | 单像素 RGB 单通道差 ≤24 视为渲染抖动（非差异像素） |
| `RATIO_TOL` | 0.004 | 差异像素占比 >0.40% → FAIL |
| 尺寸不一致 | 直接 FAIL | 布局尺寸变化零容忍（无容差） |

## 3. 抖动调查（为何换捕获方法，而非调容差）

初版用 Playwright `fullPage:true` 捕获，发现 home 页跨 run 非确定性：

| 图 | fullPage 法 run1 | run2 | 抖动区域 |
|---|---|---|---|
| home-360 | 0.5575% | 0.2758% | y1690–1812、y2004–2114 |
| home-768 | 0.1235% | 0.0000% | 同类区域 |
| 其余 7 图 | 0.0000% | 0.0000% | — |

- 红像素 bbox 与 `.ba__imgs` 内 `<img>`（logo-acme_before/after.png）矩形完全重合
  （investigation-jitter-home360-diff.png）。
- 判定：fullPage 视口展开触发图块异步重光栅化竞态（局部、仅含缩放 IMG 的区域）。
- **处置**：改捕获方法（单遍整页截图）消除抖动，而不是把 RATIO_TOL 调到 0.6% 掩盖。
  若调容差，0.4–0.6% 区间将随机误报/漏报（flaky gate）；方法收敛后抖动=0，闸门确定。
- 捕获方法变更后基线用同方法重锚（baseline-anchor-final-method.log），
  历史方法锚定记录保留（anchor-history-method1-fullpage.log，已作废）。

| 数据点 | 场景 | 差异比率 | 对照 RATIO_TOL |

## 5. C 闸职责边界（阈值语义）

- **捕获目标 = 布局位移**：任何真实 reflow（整页/整段位移）差异像素量级远超 0.40%
  （D1 实证 21%；一行文字 reflow 通常 >2000 px ≈ 0.06–1%，视图宽而定）。
- **容忍域 = 渲染抖动 + 微量内容变化**：文案级改动（D2 量级）不由 C 闸负责——
  冻结文案由 deploy-gate 的 `audit-copy.mjs` 逐字把关（既有闸，未弱化）。
- **gross 错换 = 尺寸零容忍**：TRIP3 证明换错基线全部被尺寸闸拦截（9/9 FAIL）。
- 结论：0.40% 是「容忍抖动、不容忍布局位移」语义下的保守取值，且本地抖动实测为 0，
  无任何真实回归被该阈值放行的实证。

## 8. CI 环境差异实测（2026-11-24 run 45306950102，预案已关闭）

GitHub ubuntu-latest + node22 + playwright^1.63（锁定 chromium-1243）实测：
**9 图 C 断言全部 0.0000%**（见 ci-run.md）——同浏览器构建下跨环境渲染逐像素一致，
RATIO_TOL=0.4% 余量未被消耗。重校准触发条件（若未来 runner/浏览器版本变化引入差异）：
1. CI 若因均匀分布小比率差异 FAIL（无局部聚集 = 无布局位移），记录各图比率；
2. 在本文件追加数据，将 RATIO_TOL 上调至 max(CI jitter)×2 且必须 **低于 D1 的 1/10（2.1%）**，
   并重跑三闸 trip 验证捕获余量未失效；
3. 若差异呈局部聚集（=真布局差异），不得调容差，按回归排查。
